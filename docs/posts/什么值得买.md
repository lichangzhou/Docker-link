## 正文（可直接粘贴）

### 我的 NAS 环境

家里是一台飞牛 NAS（AMD 平台，64GB 内存），上面常年跑着 20 多个容器：Jellyfin、Emby、Plex 三套媒体库，qBittorrent、MoviePilot、alist、Home Assistant、mihomo、searxng，外加一堆临时起的新容器。

最开始用的是 Portainer，说真的，用着还行。但半年之后有几个问题实在受不了了。

**一是 Compose 项目跟硬盘上的文件对不上。** Portainer 的 Stack 存的是它自己数据库里的一套，跟我 `/vol1/1000/docker/` 目录里的 compose 文件完全是两回事。我在面板上加了个容器，compose 文件根本没跟着变，下次 `docker compose up -d` 就给我覆盖回去了。后来我每次改 compose 都得 SSH 进去手改文件，再回面板点「重新部署」，特别别扭。

**二是文件管理基本等于没有。** 想看一眼 compose 文件内容，只能 SSH 进去 `cat`；想传个配置文件进去，还得开 SFTP 客户端。

**三是远程节点在 CE 版里很痛苦。** 我还有台小机器跑 Docker，管理远程节点要在网页里一个个敲 SSH 私钥、端口、密码。

**四是界面全英文。** 我不是英语母语，查参数经常得开翻译软件。

于是自己动手写了一个，叫 **Docker-Link**，周末写了两个周末，部署在自己 NAS 上用，到现在两个多月了。

### 它能干什么

容器、镜像、卷、网络、端口的完整管理，这些是基本盘，日志、终端、重启都在。

**Compose 项目管理是我最满意的部分。** 它直接扫我硬盘上真实的 compose 目录，把每个项目列出来，点进去能看到有哪些服务、哪些容器在跑、哪个挂了。编辑完点「部署」，走的是 `docker compose up -d`，不是我另造的一套逻辑。所以硬盘上的文件永远是唯一事实来源，不会出现「面板改了但文件没改」的割裂——这正是我换掉 Portainer 的最大原因。

**文件管理器**能浏览、在线编辑、上传、下载。我现在所有 compose 文件都放一个目录，直接在面板里编辑，不再开 SSH。

**Web 终端**是我用得最多的功能，点一下容器就进去，是真正的交互式 shell（`docker exec` + PTY，不是只能看不能输的伪终端）。排查问题时省掉了一大半 SSH 操作。

**多节点**支持两种方式：装 Agent 模式（HTTP + Token 认证），或者纯 SSH 通道，不用额外装东西也行。

**容器更新**做了个兜底逻辑。国内拉镜像慢，所以做了三层：先走加速源，不行直连 dockerd，再不行在容器内走代理 `docker load`。判断「有没有新版本」不是看 tag，而是**比对镜像 digest**——这个细节很关键，很多面板 tag 没变但底层镜像已经更新了，它就再也不提示更新了。

另外还有**企业微信告警**（容器挂了、更新完成直接推群里）、**图标自动匹配**。

### 怎么部署

```bash
docker run -d --name docker-link --restart always -p 9080:9080 \
  -v /var/run/docker.sock:/var/run/docker.sock:ro \
  -v /opt/compose:/opt/compose:rw \
  -v docker-link-data:/data \
  -v docker-link-config:/app/config \
  -e TZ=Asia/Shanghai \
  lichangzhou/docker-link:latest
```

打开 `http://你的NAS地址:9080` 就能用了。

### 说说缺点

自用工具做的，我觉得有必要把不行的也讲清楚：

- **目前只有 amd64 架构镜像**，ARM 机器（部分国产 NAS、树莓派）用不了，得自己构建。这点我做得不好。
- **默认没有内置认证**。它挂载了 `docker.sock`，能操作 Docker 基本等于有宿主机 root 权限，所以我自己的做法是设了 `ADMIN_USER` / `ADMIN_PASSWORD`，且只在局域网内访问。**千万别直接暴露到公网。**
- 界面是单文件打包的，好处是零构建、镜像小，坏处是功能一多代码不好维护。
- 项目还年轻，还在快速迭代，接口可能会变。

### 另外两个项目

写 Docker-Link 的时候顺带发现，光有面板不够——容器跑起来了，媒体库本身还是乱的。所以我这套环境一共三个项目，都是我自己写的：

Docker-Link 负责把容器跑起来，**EvoLink** 负责把媒体库理清楚（缺口比对 / 归档刮削 / 权重洗板 / 302 换链），**Playable** 负责在 Android / Windows / iOS 上把 `.strm` 库看下去。三个仓库都在我 GitHub 账号下：https://github.com/lichangzhou

用不着三个都装，按需挑一个就行。

如果你是自建家用，这套应该挺合身；生产环境请自己评估安全模型，别直接照抄我的配置。
