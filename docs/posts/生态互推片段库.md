### 片段 B —— 聚合链接（用于外链上限 ≥ 2 的平台）

### 片段 C —— 技术向（掘金 / CSDN，多外链场景）

> ### 附：这三个项目是怎么串起来的
>
> 单独用任何一个都能跑，但串起来才是一条完整的链路：
>
> ```
> Docker-Link（把容器跑起来 / 监控告警）
>      ↓
> EvoLink（把媒体库理清楚：缺口比对、归档刮削、13 维权重洗板、302 换链）
>      ↓
> Playable（Android / Windows / iOS 播放端，直接播 .strm，自动跟随 302）
> ```
>
> 分工上有个细节值得一提：**EvoLink 生成的 `.strm` 里写的是签名直链，用 HTTP 302 跳转到真实地址**，所以链接是有时效的。播放端必须跟随 302，不能把 `.strm` 里的 URL 当成最终地址缓存下来——否则过期后播不出来。Playable 就是按这个前提实现的。
>
> 三个仓库：Docker-Link（本篇）、EvoLink（https://github.com/lichangzhou/Evolink）、Playable（https://github.com/lichangzhou/Playable）。

用法：**+2 个外链**，仅在明确允许多外链的平台使用。

## 四、合规提醒（发布前逐条对）

- **linux.do**：站规禁跨社区引流、禁 AFF/返佣链接。三个项目同在 GitHub **不算跨社区引流**——措辞必须是「同作者的另外两个项目」，**不能**写成「去恩山看」「加我 QQ 群」「扫码进群」。片段 A 已按此口径写。
- **什么值得买**：平台明文「谢绝个人业务推广」。三个项目必须写成**自用栈的真实体验**（「我家里这套环境实际怎么跑的」），不能写成产品矩阵宣传。
- **恩山 / NodeSeek**：禁商业广告与 QQ 群引流，同上处理。
- **阮一峰 / HelloGitHub / GitHubDaily**：正文 3–5 行，长文是负分。片段 D 只占一句。
- **Reddit / HN**：「please star my repo」读起来像 spam，不要这么写。片段 E 只陈述事实。
- **同一平台不要同时发三个项目的稿件**，会被判为重复营销。**建议主推 Docker-Link 的平台只发这一篇**，另两个项目另找平台（比如 EvoLink 走周刊类、Playable 走海外）。
- **对外只提中性能力**（缺口比对 / 刮削 / 洗板 / 302 换链 / 播放）。涉及具体元数据来源与特殊分类的表述**不出现在中文消费类平台**，那是国内版仓库里的细节，公开渠道一律不提。
